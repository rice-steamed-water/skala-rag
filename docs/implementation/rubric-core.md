## 0. 공통 규칙 (14개 criterion 모두 적용)

### 0.1 상태 — 승인된 D05 기준

| 상태 | 의미 | 점수 | 결측 비중 |
| --- | --- | --- | --- |
| `observed` | 최소 근거 충족, rating 1–5 | 비중 × rating/5 | 제외 |
| `missing` | 해당 criterion의 근거로 확인 불가, 또는 적용조건 미확정(`applicability_note` 병기) | 없음 | **포함** (분모 100 고정) |

**D05(APPROVED, #3):** 전체 비중 100을 고정 분모로 쓰고, 적용조건이 불확실하면 `missing + applicability_note`로 남기며 비중을 제거하지 않는다. `not_applicable` 비중 재배분은 미채택이다. 따라서 이 14개 criterion은 `not_applicable`을 쓰지 않는다.

**v3(#35 / PR #36, 미병합)와의 관계:** v3 C-3은 not_applicable을 분모에서 제외한다. v3가 D05를 대체하도록 승인되더라도 이 14개는 N/A 금지를 유지할 것을 제안한다. 창업자·시장·기술·경쟁 우위는 모든 적격 후보(Seed–C, Physical AI/Robotics)에 적용되는 질문이고, 시장성·기술력은 v3 저점수 보류 대상이라 N/A로 분모를 줄이면 저점수 조건을 우회하게 된다. v3의 C-2 표 "N/A = Evidence 부족"은 이 문서의 `missing`에 해당한다. → Q3

### 0.2 rating을 거절하는 경우 — 반드시 missing

| 규칙 | missing_reason | 설명 |
| --- | --- | --- |
| 근거 없는 rating 금지 | `not_disclosed` | observed는 rating·rationale·실존 evidence_ids가 모두 있어야 한다([contracts](contracts.md)). LLM 일반 지식·추측으로 채우지 않는다 |
| 다른 기업 근거 오염 금지 | `attribution_unverified` | 근거의 주체가 후보(candidate_id)와 일치해야 한다. 동명 기업·동명이인·모회사/자회사·경쟁사 자료를 후보 근거로 쓰지 않는다. 회사명 문자열만으로 연결하지 않는다 |
| 미해결 상충 | `unresolved_conflict` | 같은 사실에 대한 근거가 서로 다른 rating 구간을 가리키고 해소되지 않으면 missing. 더 좋은 쪽을 고르지 않는다 |
| 참고 신호만 있음 | `proxy_only` | 수상·TIPS 선정·투자자 명성·언론 노출 빈도는 맥락이지 해당 criterion의 직접 근거가 아니다 |
| 기준일 이후 자료 | `after_as_of` | 실행 as_of 이후 근거는 쓰지 않는다 |
| 회사 자기주장만 | (rating 상한) | 회사 자료만으로 뒷받침되는 주장은 최대 4. 5는 독립 출처(고객사·논문·공공 DB·제3자 시험) 교차확인 필요 |

**산업 근거 허용 범위:** 시장성(market.*)만 후보 기업이 아닌 **산업 근거**를 쓸 수 있다. 단, 후보가 실제 진입하는 세부 시장과 일치해야 한다(예: "전체 로봇 시장" 수치로 "물류 AMR" 기업의 시장 규모를 평가하지 않는다 — 불일치 시 `segment_mismatch`). 나머지 11개는 후보 기업 자체 근거만 쓴다.

### 0.3 rating 공통 척도 (D02, v3 C-2와 정합)

| rating | v3 수준 | 배점 환산 | 공통 요구 |
| --- | --- | --- | --- |
| 5 | 매우 우수 | 100% | 복수의 신뢰 가능 근거 + 경쟁사 대비 우위, 독립 출처 교차확인 |
| 4 | 우수 | 80% | 충분한 근거로 긍정적 결과 확인 |
| 3 | 보통 | 60% | 기본 요건 충족, 차별성·근거 제한적 |
| 2 | 미흡 | 40% | 일부 근거, 위험·불확실성 큼 — 부족한 지점 명시 |
| 1 | 매우 미흡 | 20% | 부정적 근거 우세 — **낮다는 직접 근거 필요** |

"근거가 약하다"는 이유로 1–2를 주지 않는다. 근거가 부족하면 missing이다. 1–2는 **약점이 근거로 확인**된 경우다.

## 1. Founder — 창업자 (영역 비중 5)

**대상 인물:** 공동창업자 중 CEO·CTO 등 창업 시점부터 경영진인 인물. 평가에 쓴 인물을 rationale에 명시하고, 인물이 여럿이면 **가장 적합한 1인이 아니라 핵심 창업팀 전체의 대표 수준**으로 판단한다(제안 — Q4). 인물 일치(동명이인 배제: 소속·기간·분야 교차)가 안 되면 `attribution_unverified`.

### founder.expertise — 도메인 전문성 (비중 2)

**최소 근거:** 인물 일치가 확인된 전공·학위·연구 분야·논문/특허 중 하나 이상(OpenAlex·Semantic Scholar·회사 공식 프로필).

| rating | 기준 |
| --- | --- |
| 1 | 창업팀 전공·경력이 AI·Robotics와 무관함이 확인됨 |
| 2 | 인접 분야(일반 SW, 기계·전자 일반)만 확인, 핵심 기술 분야 경력 없음 |
| 3 | 관련 전공(학사/석사) 또는 관련 분야 연구·개발 경력 확인 |
| 4 | 핵심 기술 분야 박사 또는 5년 이상 연구·개발 + 관련 논문/특허 |
| 5 | 4 + 해당 기술의 주요 저자·발명자로서 외부 인정(피인용·학회·공동연구) 교차확인 |

경계 예시(가상): 로봇 제어 석사 + 로봇 기업 연구원 3년 → **3**. "왜 4가 아닌가": 박사·5년 이상·관련 논문/특허 중 무엇도 없음.

### founder.industry — 관련 산업 경험 (비중 2)

**최소 근거:** 이전 회사·직무·기간, 참여한 AI/로봇 제품·프로젝트.

| rating | 기준 |
| --- | --- |
| 1 | 관련 산업 경험이 없음이 확인됨 |
| 2 | 인접 산업 경험만 확인(제조·IT 일반) |
| 3 | 연구실·과제 수준의 AI/로봇 프로젝트 경험 |
| 4 | 기업에서 AI/로봇 제품 개발에 3년 이상 참여 |
| 5 | AI/로봇 제품의 출시·양산을 리드한 경험(팀장·책임자) 확인 |

### founder.execution — 창업·사업화 경험 (비중 1)

**최소 근거:** 이전 창업·제품 출시·사업화 참여 이력. **현 회사의 성과는 technology.commercialization에서 평가**하므로 중복 가점하지 않는다.
**missing:** 경력 전체가 확인되지 않은 상태에서 "경험 없음"으로 판단하지 않는다.

| rating | 기준 |
| --- | --- |
| 1 | 경력 전체가 확인됐고 제품·사업 관련 경험이 전무 |
| 2 | 연구·개발 경험만, 사업화 참여 없음 |
| 3 | 첫 창업이나 이전 직장에서 제품 출시·사업화 참여 |
| 4 | 이전 창업 경험 또는 제품 출시를 직접 책임진 경험 |
| 5 | 이전 창업의 Exit(인수·상장) 또는 이전 제품의 상용 성공 교차확인 |

## 2. Market — 시장성 (영역 비중 30, v3 핵심 차원)

**산업 근거 허용**, 단 세부 시장 일치 필수(`segment_mismatch`). 수치는 **출처·기준연도·지역·통화·시장 정의**가 있어야 관측이다.

### market.size — 목표 시장 규모 (비중 10)

**기준값:** 후보가 진입하는 **SAM**(공략 가능 시장). SAM이 없고 TAM만 있으면 **최대 3**. 통화는 USD 기준으로 환산하되 환율·기준일을 derivation에 기록.

| rating | 제안 구간 (SAM, 기준연도 현재값) |
| --- | --- |
| 1 | < 1억 달러 |
| 2 | 1억 ≤ x < 5억 달러 |
| 3 | 5억 ≤ x < 20억 달러 |
| 4 | 20억 ≤ x < 100억 달러 |
| 5 | ≥ 100억 달러 |

경계 예시(가상): "국내 물류 AMR 시장 2025년 8억 달러" → **3**. 같은 보고서가 "글로벌 로봇 시장 500억 달러"만 제시하면 세부 시장 불일치 → 그 수치로 5를 주지 않음.

### market.growth — 시장 성장성 (비중 10)

**최소 근거:** 같은 세부 시장의 CAGR(기간 3년 이상, 시작·종료 연도 명시) 또는 연도별 전망치(계산 시 derived).
**상충:** 출처 간 CAGR이 서로 다른 구간이면 **낮은 쪽**을 쓰고 limitations에 기록. 2개 구간 이상 차이 나면 `unresolved_conflict`.

| rating | 제안 구간 (CAGR) |
| --- | --- |
| 1 | < 0% |
| 2 | 0% ≤ x < 5% |
| 3 | 5% ≤ x < 15% |
| 4 | 15% ≤ x < 25% |
| 5 | ≥ 25% |

경계 예시: 보고서 A 18.2%, B 26.0% → 한 구간 차이 → 낮은 쪽 18.2% → **4**. B만 있었다면 5.

### market.demand — 시장 수요·확장성 (비중 10)

**최소 근거:** 세부 시장의 구체적 문제(인력난·안전·비용)와 **실제 도입 사례**(후보 외 기업 사례 포함). 후보 자체의 고객 수는 technology.commercialization에서 본다.

| rating | 기준 |
| --- | --- |
| 1 | 도입 수요가 약하다는 근거(도입 철회·규제 금지·대체 기술 우세) |
| 2 | 문제는 있으나 도입 사례가 거의 없고 장애 요인(규제·비용)이 큼 |
| 3 | 문제와 도입 사례가 확인되나 한 산업에 국한 |
| 4 | 복수 기업의 도입 사례 + 인접 산업 확장 근거 |
| 5 | 4 + 공공 정책·산업 통계로 수요 증가가 교차확인되고 2개 이상 산업에서 도입 확산 |

## 3. Technology — 제품/기술력 (영역 비중 25, v3 핵심 차원)

후보 기업 자체 근거만 사용. 회사 자기주장만이면 최대 4.

### technology.maturity — 핵심 기술 완성도 (비중 10)

**최소 근거:** 제품 개발 단계의 직접 자료(시연 영상·인증·출시 발표·기술 문서). 회사가 밝힌 TRL은 이를 뒷받침하는 사건(시연·인증·출시)이 있을 때만 인정.

| rating | 기준 (TRL 대응) |
| --- | --- |
| 1 | 개념·기초 연구 단계 (TRL 1–3) |
| 2 | 실험실 시제품 (TRL 4–5) |
| 3 | 실제 유사 환경 시연 (TRL 6) |
| 4 | 실제 운용 환경 파일럿·인증 완료 (TRL 7–8) |
| 5 | 상용 제품 판매·운영 중 (TRL 9), 제3자 확인 |

경계 예시(가상): "고객사 창고 3곳 파일럿 운영, KC 인증 완료" → **4**. "왜 5가 아닌가": 유료 판매·상용 운영 확인 없음.

### technology.reliability — 실제 환경 성능·안정성 (비중 5)

**최소 근거:** 테스트 조건(환경·기간·작업)과 결과 수치(성공률·가동률·오류율 등).

| rating | 기준 |
| --- | --- |
| 1 | 현장 실패·리콜·안전사고 근거 |
| 2 | 실험실·통제 환경 결과만 확인 |
| 3 | 실제 환경 실증 사실은 확인되나 수치 제한적 |
| 4 | 실제 환경 테스트 수치 공개(조건 명시) |
| 5 | 고객 현장 장기 운용 지표가 고객사·제3자 자료로 교차확인 |

### technology.integration — AI·HW·SW 통합 역량 (비중 5)

## 4. Moat — 경쟁 우위 (영역 비중 20)

### moat.differentiation — 경쟁사 대비 차별성 (비중 5)

**최소 근거:** **이름이 명시된 비교 대상**과 비교 항목. 비교 대상 없는 "업계 최고" 주장은 `proxy_only`.

### moat.ip — 기술·특허 진입장벽 (비중 5)

**최소 근거:** KIPRIS·Google Patents·WIPO 등에서 **출원인 식별이 확인된** 특허 목록과 핵심 기술 관련성. 검색 0건만으로 "특허 없음(1)"을 주지 않는다 — 출원인명 변형(국·영문, 법인 전환)까지 확인한 경우에만 1.

| rating | 제안 기준 (핵심 기술 관련 특허) |
| --- | --- |
| 1 | 출원인 식별 확인 후 관련 특허·출원 없음 |
| 2 | 출원만 소수, 핵심 기술 관련성 낮음 |
| 3 | 핵심 관련 등록 특허 1–2건 또는 출원 다수 |
| 4 | 핵심 관련 등록 특허 3건 이상 또는 해외 출원(Patent Family) |
| 5 | 핵심 관련 등록 특허 10건 이상 + 해외 Family + 피인용(Forward Citation) 확인 |

## 5. missing_reason 코드 (재무 rubric과 공유 + 추가)

재무 rubric의 코드(`not_disclosed`, `period_mismatch`, `currency_mismatch`, `unresolved_conflict`, `proxy_only` 등)를 공유하고 다음을 추가한다.

| 코드 | 의미 |
| --- | --- |
| `attribution_unverified` | 근거 주체가 후보와 일치함을 확인하지 못함(동명 기업·동명이인·관계사) |
| `segment_mismatch` | 시장 근거의 세부 시장이 후보의 진입 시장과 다름 |
| `after_as_of` | 실행 as_of 이후 근거 |
