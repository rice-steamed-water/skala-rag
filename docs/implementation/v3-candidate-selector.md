# #89 v3 candidate selector (fixture-only)

`graph.candidates_v3.run_candidates_v3` is a separate, synchronous all-candidate controller. It invokes the actual `graph.evaluation_v3.build_evaluation_graph_v3` LangGraph for **each eligible candidate**: five parallel terminal branches, the five-result join, then six promoted evaluations. It never calls baseline `graph.candidates.build_candidate_graph`, `scoring.aggregate`, or `scoring.decide`, and it does not stop on a recommendation.

The caller injects discovery, normalization, research, eligibility, collection and freeze stages, plus five evaluators, a support check and **external approved** applicability checks. The controller calls #20 `check_coverage_v3` before freeze and #24's evaluation graph after freeze. It compares the explicitly supplied baseline catalog policy ID, criterion IDs/dimensions/weights, and dimension weights with the v3 configuration. Eligibility schema/run/candidate/policy and freeze generation must match. Frozen Evidence must be identical in the full JSON DTO dump to collected Evidence for that candidate or collected industry scope; collected entries may be omitted. Source/Chunk/RetrievalRecord references in the frozen snapshot must close before evaluation. These fixture checks do not prove live source authenticity, allowed-source/as-of admission, or actual retrieval. Only a successful six-dimension promotion is scored. #24 owns branch failures and its single archive/advance; this controller verifies the increment and advances other terminal outcomes once. A stale snapshot or malformed result fails only its candidate. No stage/provider exception text enters the returned redacted error.

`scoring.aggregate_v3` computes original weighted points, missing-inclusive/N/A-exclusive applicable denominator, dimension ratios and normalized score. Each N/A additionally requires a supplied verifier; the #20 and #24 checks separately validate applicability and frozen Evidence attribution. A zero denominator in **any** dimension raises `ZeroDenominatorV3` and records `ZERO_APPLICABLE_DENOMINATOR`, so there is no score/label for that candidate. `scoring.decision_v3` applies missing ≥30% and market/technology ≤40% before the exact, unrounded 80/70/60 comparisons. `scoring.selector_v3` orders eligible normal results by label priority, score descending, missing ascending, then **original** candidate ID ascending; WATCHLIST/PASS alone produce no selection.

`CandidateRunV3` is the versioned handoff: `status`, `candidate_index`, all candidate outcomes, v3 scores/decisions, `SelectionResultV3`, errors and explicit `reporting_gap`. `baseline_report_input` is always `None`. A v3 `ReportInput`/ReportContext adapter and report-context validation are **not** supplied; feeding these v3 payloads to the baseline report graph is forbidden. `ready_for_v3_reporting` describes an upstream handoff, not a completed report or publishable result. Distinct statuses include `no_candidates`, `discovery_failed`, `no_eligible_candidates`, `all_eligible_failed`, and `eligible_failed_no_success`.

This controller does not choose the pre-evaluation random candidate set, approve D14 rubric/applicability rules, implement #25's bounded research retries, generate a report/CLI result, or enable live execution. In particular, injected callbacks and synthetic evidence are not provider measurements or an approved default policy. Integration fixtures use synthetic evaluations; the actual #24 LangGraph executes, but no live service is contacted.
